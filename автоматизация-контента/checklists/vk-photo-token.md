# VK: картинки к посту

## Пауза публикации постов

`VK_PUBLISH=off` — **новые посты и VK-тизеры не публикуются**.
Слоты `publish_vk_post` остаются `scheduled`. TG / Дзен / TG-тизеры идут как обычно.
Вернуть: `VK_PUBLISH=on` в `.env`.

## Режим картинок: вручную (по умолчанию)

`VK_PHOTOS=manual` — скрипт публикует **только текст**.
Картинки Мария прикрепляет сама в VK к уже вышедшему посту.

Пайплайн обложек (Codex на ПК): `checklists/covers-codex-pc.md`.

Готовые файлы обложек:
- локально: `assets/covers/{id}-vk.jpg` (1080×1080)
- на сайте: `https://blog.mkekspert.ru/covers/{id}-vk.jpg`

Пример: после поста `vk-week3` открыть стену → изменить → прикрепить
`https://blog.mkekspert.ru/covers/vk-week3-vk.jpg` (если файл есть).

Не вызываем `VK_USER_TOKEN` / `photos.getWallUploadServer` / recycle.

## Автозагрузка: требуется подтверждённый способ подключения

10 октября 2026 пользователь передал ответ поддержки VK: некоторые сторонние приложения могут ограничиваться из-за нарушений при работе с API. Ответ общий и не подтверждает конкретную причину нашей ошибки или срок её снятия.

В проекте проверялись пользовательские ключи через Kate Mobile (app_id 2685278). Исходный запрос photos.getWallUploadServer и проверка после замены ключа wall.getById получили код 9, Flood control. Повторная выдача ключа не устранила отказ. Пользовательский ключ исключён из активных настроек; текстовые публикации через ключ сообщества включены.

Не использовать Kate Mobile или чужие app_id для выдачи новых ключей этого проекта. Не извлекать токены из официальных мобильных приложений и не выполнять flood-пробы. Не использовать старые пользовательские ключи из приватных резервных копий для проверки канала.

До подключения изображений запросить у поддержки VK официальный разрешённый вариант для публикации фото на стене собственного сообщества: доступ ключа сообщества либо собственное приложение с нужными разрешениями. Создание приложения или авторизация VK ID сами по себе не подтверждают доступ к photos.*.

После подтверждения разрешённого способа и явного поручения пользователя выполнить одну проверку на существующей записи. Только подтверждённый успешный результат позволяет включать VK_PHOTOS=auto. При неопределённом сетевом результате сначала проверить публикацию; при отказе не запускать повторов в цикле.

Отзыв авторизации приложения выполняет пользователь в кабинете VK ID, раздел «Сервисы и сайты»: https://id.vk.ru/account/#/services. Отключение ключа на сервере само по себе не отзывает выданное приложению разрешение.
