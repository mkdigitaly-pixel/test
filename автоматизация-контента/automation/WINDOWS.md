# Запуск mkekspert на ПК

Рабочая папка: `D:\Маша\VS code\mkekspert`.
Код и редакционные материалы: `repo\автоматизация-контента`.
Настройки с ключами: `private\automation.env`. Папка `private` доступна текущему пользователю Windows и SYSTEM; она находится вне Git. Доступы Tilda и пользовательский ключ VK не перенесены в исполнитель публикаций.

## Как работает расписание

Задание Windows `mkekspert-content` проверяет очередь каждые 5 минут и запускается после входа текущего пользователя в Windows. При сбое процесса предусмотрены три повтора через минуту. ПК должен быть включен, пользователь должен войти в Windows, спящий режим должен быть отключен на время ожидаемых публикаций, интернет должен работать. Закрытие Codex или VS Code само по себе не останавливает это задание. Настройки питания автоматически не изменяются.

Время публикаций берется из очереди с часовым поясом Asia/Yekaterinburg. На пропущенные дни новые посты автоматически не создаются. Сохраняются действующие ограничения на опоздавшие слоты и проверку фактов.

Отправлять может только один исполнитель: либо сервер, либо этот ПК. Нельзя включать серверное расписание, пока включено задание Windows и `private\runtime-state.json` содержит `enabled: true`.

Журнал: `logs\mkekspert-content.log`. При размере больше 10 МБ он переименовывается перед следующим запуском. Журналы и настройки в GitHub не сохраняются.

## Проверка без публикации

В PowerShell:

```powershell
& 'D:\Маша\VS code\mkekspert\repo\автоматизация-контента\automation\run-windows.ps1' -RuntimeRoot 'D:\Маша\VS code\mkekspert' -DryRun
Get-ScheduledTask -TaskName mkekspert-content
Get-ScheduledTaskInfo -TaskName mkekspert-content
```

Проверка использует ту же очередь, но не отправляет сообщения и не меняет результаты. Секреты из `private` не открывать в чат и не добавлять в репозиторий.

## Пауза

Сначала выключить задание Windows и поставить `enabled: false` в `private\runtime-state.json`. Для редакционной паузы дополнительно сохранить действующие флаги `AUTO_PUBLISH=false`, `DRY_RUN=true`, `VK_PUBLISH=off`. Не возобновлять публикации автоматически после паузы.

## Возврат на сервер

1. Выключить задание Windows, поставить локальный `enabled: false` и дождаться завершения работающего процесса.
2. Сохранить последние подтверждения в GitHub. Если отправка имела неизвестный исход, проверить сам канал до любого повтора.
3. На сервере обновить рабочую ветку и четыре файла очереди последними подтвержденными результатами с ПК. Проверить частичные и неизвестные отправки, просроченные слоты и паузу.
4. Только после этого восстановить сохраненный файл серверного cron. На ПК задание оставить выключенным.

VPN, парсер и другие серверные службы не относятся к этому переносу. Перенос публикаций не заменяет VPN и не отменяет сервер у провайдера.

## Что остается в интернете

Telegram, VK и Дзен остаются внешними площадками. Блог размещается в GitHub Pages. ПК хранит рабочий проект, запускает очередь и сохраняет публичные результаты в GitHub. Рабочие SSH-ключи для GitHub находятся только в `private`; отдельный ключ ПК имеет доступ к одному репозиторию.

## Сохранение и восстановление

Если связь с GitHub оборвалась после сохранения подтверждения, следующий запуск повторяет только сохранение уже созданного коммита. Повторно отправлять опубликованный пост для этого не нужно. Секреты и посторонние подготовленные файлы в коммит подтверждений не включаются.

Локальная копия для восстановления: `private/backups/mkekspert-recovery-2026-11-22.zip`. Архив содержит закрытые настройки и ключи, поэтому его нельзя публиковать или прикладывать к чату. Публичная история кода и подтверждений остается в GitHub. В папке tools/git хранится независимая копия Git; при запуске не требуется установленный Codex. В архиве сохранены версии Python-библиотек и установочные пакеты для этой Windows/Python 3.14.

При восстановлении сначала выключить задание и установить enabled=false в private/runtime-state.json. Распаковать снимок в ту же рабочую папку, восстановить Python-окружение по private/runtime-requirements.lock.txt с пакетами из private/recovery-wheels, проверить имя ПК и актуальные подтверждения GitHub. Установщик задания всегда создает его выключенным. Перед включением убедиться, что прежний исполнитель отключен; проверить очередь и пропущенные слоты.

## Запуск без мелькания окна, 23 ноября 2026

Действие задания запускает .venv/Scripts/pythonw.exe с automation/run_windowless.py. Этот процесс задает скрытое состояние окна до создания дочернего PowerShell; Python, Git и остальные дочерние команды наследуют скрытую консоль. Прежний прямой запуск powershell.exe с одним параметром WindowStyle Hidden больше не используется как действие задания. Основной run-windows.ps1, очереди, интервалы и правила публикаций сохранены.

Прежние параметры задания сохранены в private/task-before-window-fix-20261123.xml. Текущий установщик создает задание с pythonw. При восстановлении из снимка 22 ноября применить также private/backups/mkekspert-startup-fix-2026-11-23.zip или обновить код из GitHub до установки задания. Исходный большой архив не перезаписывался.

## Нативный вывод PowerShell, 25 ноября 2026

Обычные сообщения Git в stderr не должны прерывать Python в Windows PowerShell 5.1. Wrapper временно использует Continue только для нативного вызова, пишет оба потока в журнал и проверяет код процесса; ошибки записи журнала остаются аварийными. Обработка ненулевого кода и отсутствие видимого окна проверены. Деплой блога использует detached-копию и не переключает занятую gh-pages. При восстановлении из старого снимка применить также private/backups/mkekspert-publication-fix-2026-11-25.zip или получить актуальный код из GitHub.
